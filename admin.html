Typography

MONO is the original. SANS is this machine's interface font. WIDE has the most open letterforms and is usually the easiest to read as light text on black. Three sizes only — the layout is measured in pixels, and a wider range would push labels through the sides of their buttons. This panel takes the face and size it is setting, so you read the choice while making it.

Who is speaking

The two labels down the left of the transcript. Either can be a variable instead of a fixed word: {name} — the word you say to reach whichever assistant is answering, so renaming that renames this. Already what the greeting and farewell fields use. {assistant} — what answered, which is its own field on each endpoint. This is the default, and with more than one endpoint it is the only label that can be right: a fixed word attributes every answer to the same name. Each line keeps the name of whoever gave it, so switching endpoints mid-conversation does not rewrite what is already on screen. {display} — the name of the display this is being viewed at, from ?display= on the URL. Put it in the person and each dedicated display attributes the transcript to itself, without a setting per display. An admin-set label per URL arrives with identity; this is the identifier it will hang off, so what you write now keeps meaning the same thing. Mix them with ordinary text — {display} shift lead is fine. A variable that resolves to nothing falls back to the default, and one that is not recognised is left standing so a typo is visible rather than silent.

Reach & sign-in

Which addresses the server answers on. Binding one address rather than every interface is worth doing on its own account: a laptop that later joins another network does not follow you onto it. This machine only needs no certificate — browsers already treat http://localhost as a secure origin, so the microphone works unprompted and nothing crosses a network. Start it, open localhost, talk to it.
What it takes to reach this configuration page. Nothing is for a machine only you can reach, where the network is already the boundary and accounts add nothing — and it is what makes a personal install possible without fishing a generated password out of a log. Accounts & roles is the default, because the safe default is the one that assumes it can be reached. A single PIN — one number for the whole display, no account management — is the middle rung and is not built yet. It is the PIN machinery from identity pointed at a display rather than a person, so it lands with that.

Ports

Which port each interface answers on. The two display ports serve the AI interface people use; the admin port serves this page.
Must be 1024–65535 and all different. Below 1024 needs root, and the server runs as an ordinary user.

Sessions

Idle minutes before an admin has to sign in again. Activity pushes the deadline out; the panel checks every 45 seconds and returns you to the sign-in as soon as it lapses. Short by default — this session configures what everyone else is looking at. 5 to 480. Full reasoning in DOCUMENTATION → App settings & accounts.

Embed keys

A key lets another application's server ask this one for a short-lived session and put the result in an iframe. The key never reaches a browser. What it may do and what it draws are fixed at creation — to change either, make a new key and retire this one. 1 their server POSTs the key to /embed/session 2 their page frames /embed?t=… with allow="microphone" 3 optionally narrows it at runtime over postMessage — never widens The one everybody hits: a microphone in an iframe needs allow="microphone" and the host page on HTTPS and the permission granted on their origin. Miss one and it looks broken for reasons that have nothing to do with this server. Worked examples in DOCUMENTATION → Embedding it elsewhere.
